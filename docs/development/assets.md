# 资产版本与流程依赖

## 核心接口

`Assets(workspace)` 提供正式资产存储，和流程服务共用工作空间写锁、请求预算及 SQLite 事务。可信的导入、编辑及录制应用服务使用 `put(asset_id, name, kind, source, expected_version=None, duration_us=None)` 写入资产；`source` 是二进制读取流，`kind` 是 image 或 trajectory。返回资产身份、不可变版本、原始内容摘要、长度、媒体类型和内容元数据。

首次登记的 expected_version 为 null；更新时必须给出当前版本。资产身份保持类型不变，新内容追加版本并移动头版本。资产身份最长 256 字符；名称按 NFC 归一化后检查 1～256 字符、保留大小写，同种资产的名称唯一。图像共享 image 名称空间。名称占用、版本、目录有效区间和内容分块索引在同一事务提交，冲突整笔回滚。

解码、内容摘要及块索引从同一私有暂存字节流生成，再发布该流的原始字节。二进制对象按 SHA-256 寻址，每项最多 1GiB，以 192KiB 块读写；对象文件刷新并原子发布后才登记元数据。相同摘要复用相同内容，已登记文件缺失或损坏返回 STORAGE_CORRUPT。未引用文件留在对象存储中；其回收须遵循[数据设计](../design/storage.md)的全局强引用与延迟回收规则。

图像支持 PNG、JPEG、WebP、BMP、GIF、TIFF 和 ICO，通过 Pillow 的指定格式解码器实际解码，检查完整文件结构及全部帧，累计解码像素最多 64,000,000；媒体类型、尺寸和帧数来自解码结果。轨迹校验公共格式、显示拓扑、坐标模式、来源单位、时间顺序和按下/释放配对，原始字节完整保存。相同时间戳按原数组顺序保留，每个事件满足 atUs < durationUs；未传 duration_us 时取最后事件时间加一微秒。

## 流程保存与复制

[依赖契约](../../contracts/dependencies.schema.json)中的逻辑键准确覆盖流程 resources，类型逐项一致。图像和轨迹绑定 kind、assetId、assetVersion、sha256；子流程绑定 kind=workflow、workflowId、revision。绑定必须指向当前工作空间中已存在的正式版本，不能按名称寻找替代对象。

保存从完整依赖图检查资产读取权、子流程读取权和每个子流程的授权范围，并校验内容完整性。缺失版本返回 RESOURCE_NOT_FOUND，身份、类型或摘要不匹配返回 DEPENDENCY_MISMATCH，依赖循环返回 DEPENDENCY_CYCLE。失败不登记新版本或保存回执。

内嵌子流程 definition/dependencies 成对接收，先与指定正式版本核对，再规范化为固定版本引用。workflow.read 返回这一规范形式。复制流程保留引用即可共享同一不可变依赖；跨工作空间交换使用包含完整内容的任务包。内嵌对象不能创建或覆盖指定的正式子流程版本。

图遍历按不可变版本去重，共享子图只读取一次；最多 10,000 个依赖版本、100,000 条受检查的绑定关系。遍历时间为 O(V+E+S)，S 为本次校验的内容字节数；图索引空间为 O(V+E)，文件摘要计算使用固定块缓冲。子流程只保存直接版本引用，不将共享依赖反复内嵌展开。

流程版本、直接资产/子流程强引用、头版本和幂等保存回执在同一事务提交。引用外键拒绝删除仍在使用的版本；资产头更新保持旧绑定。相同请求标识与参数重试返回原版本，参数变化返回 REQUEST_CONFLICT。

## 查询与资源读取

`workspace.catalog(kind=asset)` 使用与流程目录相同的名称筛选、排序和稳定分页。首请求固定版本有效区间，更新资产名称和头版本不会改变已有分页内容；pageSize 最大 100，完整结果最多 256KiB，游标绑定会话与授权版本。

`asset.read` 需要 asset.read 权限及 contentRefsV1 能力。offset/length 选择指定版本的原始字节区间，length 最大 4MiB，超过尾部时返回剩余字节，offset 等于总长时返回空区间，超过总长则拒绝。返回资源描述中的 length/sha256 对应该区间；媒体类型沿用资产原媒体类型。调用方通过 resource.read 从区间内部偏移 0 开始分块读取，拼接多个区间后使用资产绑定中的 sha256 核对完整文件。

范围读取只读取并校验覆盖该区间的内容块，I/O 为 O(length+块大小)。块摘要索引随资产登记提交；索引或块损坏即拒绝读取。资源属于创建会话，60 秒到期，受 16 项/64MiB 输出容量约束；释放资源、撤销会话和关闭 Engine 时回收临时内容。资源副本与原始资产版本分开持有，读取结果不会因资产头更新而变化。

## 持久化格式

资产存储在数据库格式 3 中引入；当前格式 4 的运行持久化扩展见[运行计划](run-plans.md)。资产结构在单次事务中增加 asset、asset_version、asset_name_claim、blob_chunk、revision_asset_ref 和 revision_workflow_ref。格式 1/2 的既有流程版本、对象和保存回执保持原内容；初始化失败回滚，重新打开后继续按原格式处理。数据格式由支持相应格式的 Engine 读取，旧 Engine 拒绝写入。

## 验证

`uv run --frozen python -m unittest tests.engine.test_assets -q` 覆盖版本重开、名称冲突、真实图像解码、轨迹格式与事件连续性、依赖规范化、跨层授权、共享子图、引用外键、原子回滚、范围读取和目录快照。
