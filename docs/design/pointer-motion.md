# 连续指针运动与笔画回放

## 动作含义

录制绘图需要保留整条笔画的中间位置、先后顺序、转折、停顿和按钮状态。回放时，目标画布应在移动过程中逐步画出该笔画。只到达终点、只保留累计位移、移动完成后连接首尾，均不满足连续轨迹要求。

| 输入来源 | 执行方式 | 路径规则 |
|---|---|---|
| `input.trajectory` | 按事件种类、数组顺序及 `atUs` 调度 | 保持已有点列和原始增量；不自动拟合、随机化、抽样或压成首尾 |
| `pointer.move` | 从当前物理位置到指定位置，按 `durationMs` 生成运动 | 正时长生成连续中间点和连续速度；零时长表示单次定位 |
| `pointer.delta` | 在指定时长内分配明确的相对增量 | 分步增量之和严格等于请求值，不能以屏幕位置替代 |
| `pointer.drag` | 定位起点、按下、持续移动、释放 | 正时长在按钮持续按住期间发送全部中间运动；完整曲线使用轨迹资产 |

同名 `pointer.move` 在动作节点中表示生成一次运动，在 Trajectory 中表示一个已有采样位置。执行器不得把轨迹事件逐条交给带默认动画的动作实现，也不得把一整段轨迹重建成一个普通拖拽动作。

## 共享语义与平台后端

完整点列、按钮生命周期、调度、暂停和积压处理由共享核心执行；原生采集与发送按 Windows、macOS、X11、Wayland 后端实现。Trajectory 1.1 的屏内像素、相对量单位及运行能力见[跨平台架构](../architecture/platforms.md)。下文的 Win32 标志只适用于 Windows；macOS 使用 dragged 事件，X11/Wayland 分别处理输出缓冲、设备与会话边界。

## 事件采集

Windows 桌面绘制使用原生鼠标事件携带的位置：在启用每显示器 DPI 感知的原生接收线程中，从低级鼠标回调的 `MSLLHOOKSTRUCT.pt` 取得该事件的屏幕坐标。按钮和滚轮回调携带的位置在必要时先形成同一时刻的位置锚点，再记录对应操作。不能在后台逐包处理时调用当前光标查询，将查询结果当成各个历史事件的位置。[位置字段](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-msllhookstruct)的坐标语义在转换入口统一处理。

相对输入从 Raw Input 包保留带符号的原始增量。Raw Input 不受控制面板鼠标速度设置影响，而相对输入注入可能受系统鼠标设置影响；原始增量不是桌面物理像素。[原始鼠标包](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-rawmouse)与桌面位置使用不同语义，不按一对一关系拼接，也不以“当前光标可见或未锁定”为由相互替换。

`coordinateMode=physical` 使用全局物理位置；1.1 的 `display` 使用带显示身份的屏内像素；`relative` 使用已声明单位的相对增量；`event` 结合来源坐标空间与事件 kind 决定语义。桌面绘图在 event 模式中记录来源坐标空间中的位置；相对输入来源只在明确采用该来源的录制路径中产生 `pointer.delta`。同一次运动不能同时写入等价的绝对和相对事件。回放固定使用各事件已有语义。

回调只完成位置和按钮快照、单调时钟取样、递增序号及有界队列写入，不执行磁盘操作、界面更新、图像计算或同步 IPC。保真单位为操作系统原生接收入口报告的事件。内部序号用于维持接收顺序；写入 Trajectory 后由数组下标维持同一时间的顺序。`atUs` 来自原生接收入口的单调计时；毫秒消息时间和批量读取时刻不能被扩写成未采集到的高频历史时间。窗口消息泵、记录写入与 UI 预览分离。

`includePointerMotion=true` 默认保存全部运动。设为 false 时，仅省略没有鼠标按钮按住的普通移动；点击、滚轮前的必要位置锚点及任意按钮按住期间的所有运动仍保存。绘制、套索、滑块和跨屏拖拽不能因该开关退化为首尾连线。相对模式省略的自由运动不换算成绝对锚点。

## 存储、编辑与传输

完整事件按顺序写入录制分段，UI 的抽样点、时间轴包络和画布缩略图使用派生数据。预览抽样不能回写源事件，保存、导入、导出、资源封存和再次打开均使用完整点列。相同位置在不同时间、不同笔画或非相邻位置出现时，仍可能表示停顿、闭合或交叉，不按坐标去重。

每条 Trajectory 最多 100,000 个事件，资源仍受 32MiB 限制；任一限制先达到即结束当前分段。不能为延长录制而静默降低采样率。队列溢出以 `INPUT_QUEUE_OVERFLOW` 中断，确认接收通道失效以 `INPUT_CAPTURE_LOST` 中断；两者均设置 `partial=true`，保存截至最后一条完整接收事件的分段，不跨缺口连线。该分段进入编辑草稿，不能自动发布为完整可回放资产。后续新建录制使用新时间轴。

显式裁剪、移动点、修改时间和配对修复使用可撤销编辑；未修改的事件保持原值及相对顺序。坐标映射按[录制设计](recording.md)处理；映射不得引入平滑、缩放或把空隙中的点夹到显示屏边缘。

## 原生回放调度

Engine 提交已封存的轨迹资源，Rust Agent 在发送前完成结构、配对、坐标、目标和容量检查，随后在原生线程逐事件调度。React 帧循环、WebView 定时器和 Python 的逐事件往返调用不承担原生发送时序。

事件初始期限为 `originUs + atUs + pausedUs`；首事件非零等待保留。同一时间按数组顺序发送，按钮按下之后才发送该笔画运动，最后一个运动已完成对应后端的原生提交后才发送释放。一次资源上传或一次 `segment.submit` 可以承载整段轨迹，但不能据此将不同未来期限的原生输入一次性全部注入。

每次发送前检查撤销与暂停，核对目标及拓扑代次；发送后按可确认的原生提交边界推进 `nextEventIndex`。系统部分接受且完成位置不明时进入 uncertain 和清理流程，不猜测重发。`MOUSEINPUT.time` 只是事件时间戳，不能用它代替等待事件期限。

正常调度保持绝对期限。发生积压时，不丢弃中间点、不跳到终点，也不把多个不同期限的积压事件在一个无等待循环中追发。允许在抖动预算内将整个未发送后缀一起顺延，保留该后缀的相邻时间间隔与全部按钮事件；已发送事件不改动。初始预算为单次迟到 20ms、累计顺延不超过 `max(50ms, 原始段时长的 2%)`。超过任一预算时返回 `INPUT_TIMING_OVERRUN`，在已确认边界暂停并释放程序持有输入；不能返回 sent。顺延量用于本段时长计算，不能用修改源 `atUs` 隐藏时序变化。

时序超限时，`segment.status` 返回 paused 和 pauseId，`lease.status` 的 reason 为 INPUT_TIMING_OVERRUN，携带同一实时 pauseSnapshot；Engine 据此进入运行暂停并显示输入调度延迟。累计顺延值保存在当前 Agent 的在途段调度状态，与游标一起冻结；remainingDelayUs 按顺延后的期限计算，继续沿用同一顺延值，不从原 atUs 直接追赶。Agent 重启后该实时状态失效。

普通暂停和时序超限均采用已有实时检查点，规则见[执行设计](execution.md)。暂停释放会结束目标画布当前笔画；继续时恢复输入形成新的手势，不能在预览或结果中自动补线将其合成未中断的笔画。急停、撤权和停止优先于等待与顺延。

## Windows 输入后端

| 路径 | 原生发送要求 |
|---|---|
| 桌面绝对位置 | `SendInput`，使用 `MOVE | ABSOLUTE | VIRTUALDESK | MOVE_NOCOALESCE` |
| 相对增量 | `SendInput`，使用 `MOVE | MOVE_NOCOALESCE`，保留带符号增量 |
| 鼠标按钮 | 仅在 down/up 事件改变状态，移动过程中不重复按下或提前释放 |
| 轨迹中间位置 | 使用与普通连续移动相同的原生输入流，不以只设置光标位置的接口替代 |

`MOUSEEVENTF_MOVE_NOCOALESCE` 对应 0x2000，用于阻止系统合并 `WM_MOUSEMOVE`；不把该标志理解成目标应用已经绘制完成。[MOUSEINPUT](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-mouseinput)规定绝对值归一化到 0～65535；`VIRTUALDESK` 将其映射到完整虚拟桌面。使用有符号、足够宽的中间整数处理虚拟原点、负坐标和尺寸，最后才归一化。

发送前检查每个位置属于授权显示区域的并集；归一化使用固定拓扑，不能逐屏重新建立原点。边缘、角点、跨屏边界与混合 DPI 均在实际目标窗口校准取整；无法表达所需像素精度的拓扑在准入阶段返回具体范围错误，不静默夹取。系统接收数量来自 [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput) 的返回值；目标窗口收到的事件及绘制结果单独验收。

相对输入不通过修改系统鼠标速度或加速度设置来补偿。需要屏幕绘图精度时选择物理位置来源；需要相对输入时，按该目标应用实际接收的输入类型验收。

## 自动生成的平滑运动

正时长 `pointer.move` 和 `pointer.drag` 默认在已确定的直线路径上使用五次时间曲线 `s(u)=10u³-15u⁴+6u⁵`，`u` 为 0～1 的时间比例，起止速度与加速度为零。生成步骤以时间和空间误差预算选择，不能固定为少量点后只检查终点。原生等待与发送复用轨迹调度器，不在每个中间点重新启动一次完整缓动。

整数坐标按累计目标位置取整；相对分步量使用本次累计目标与已发送累计量之差计算，避免逐步取整丢失小增量或负增量。最后一个事件严格落在指定终点，或完成请求的全部相对量。长路径分批计算但不改变已固定时间轴；超出调度或容量预算在发送前拒绝。

`durationMs=0` 保持单次定位或单次位移语义。正时长拖拽必须在持续按住期间逐步移动。需要弧线、复杂路径或特定速度变化时，使用带明确点列和时间的轨迹资产；自动生成的平滑运动不覆盖录制资产，也不对录制笔画附加随机偏移。

## 编辑器与预览

时间轴按每个按钮的 down/up 区间标记笔画，提供完整事件数、当前时间和物理位置；停顿、抬笔与重新按下保持为独立区间。显示屏布局预览采用同一全局物理坐标变换，不分别缩放各屏轨迹。

“播放预览”只推进本地时间游标并逐步显示已有路径；中途拖动游标按当时已发生的事件恢复画面，不能总是显示整条最终线。预览不发送桌面输入。“记录连续指针运动”开关说明其只省略未按住时的普通移动，绘制期间仍完整记录。资源无法完整读取时保留错误状态，不能以首尾连线代替路径。

## 原生验收

使用独立绘图窗口的固定一像素画笔，绘制器只连接实际收到且按钮按住的相邻位置。测试输入、后端实际提交结果、窗口实际接收和最终笔画像素分别核对。浏览器画布同时读取 `getCoalescedEvents()` 中的实际点；不能使用待发送点列直接绘制测试结果。

| 样例 | 必须区分的结果 |
|---|---|
| [折线](../../examples/trajectories/drawing-corners.json) | 保持转折和绘制方向，不穿过拐角连成首尾直线 |
| [闭合圆环](../../examples/trajectories/drawing-loop.json) | 起终点相同且路径长度大于零，回放画出完整圆环 |
| [八字形](../../examples/trajectories/drawing-eight.json) | 保持两叶、交叉位置和经过交叉点的先后顺序 |
| [多笔画](../../examples/trajectories/drawing-multistroke.json) | 两笔之间抬笔移动不产生连接线，各笔在运动过程中出现 |
| [相对折返](../../examples/trajectories/drawing-relative.json) | 累计位移为零仍发送全部非零中间增量，目标接收与请求顺序一致 |
| [跨屏圆环](../../examples/trajectories/drawing-cross-screen.json) | 持续按住跨越负坐标和不同 DPI 显示屏，形状与时间轴连续 |

源事件在保存、编辑未修改区、导出、导入和封存后逐项相同。Windows 全局物理坐标测试在虚拟桌面尺寸不超过 16384×16384 的矩阵内，屏内坐标测试按各显示屏的实际像素范围进行。按序比较目标接收折线与来源折线，连续 Fréchet 距离不超过 2 个对应显示屏像素；笔画数、闭合关系、转折及交叉顺序一致，笔画进行到一半时已出现对应前半段。不能用无序点集距离、总位移、总时长或最终光标位置代替这些检查。

125Hz、500Hz 和 1000Hz 的合成输入分别持续 30 秒检查录制接收、完整写入与回放调度。高于当前准入能力的速率、队列溢出、20ms 以上调度阻塞、UI 忙碌、资源写入失败和拓扑变化分别检查中断或暂停；任何失败都不能静默变成抽样成功。Q50～Q53 定义相应场景。
