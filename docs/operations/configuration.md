# 配置、可观测性与容量

## 类型化配置与所有者

设置键、类型、默认值、可写作用域和生效方式以[设置目录](../../contracts/settings-catalog.json)为准，结构受[设置契约](../../contracts/settings.schema.json)约束。未知键、超范围值和不允许的作用域整批拒绝。设置对象不接受 URL、文件路径、密钥、TLS 材料、令牌、能力引用或任意扩展项；模型连接和网络监听使用各自的专用本地方法。

基础层次为应用默认 → 用户 → 工作空间。用户作用域只展示默认与用户值；工作空间作用域合并全部三层。流程和运行只能覆盖目录 runOverrides 明确列出的业务参数，使用相应流程/运行方法自己的字段，不能传入通用 settings 对象。实际运行封存合并后的非敏感值与来源；新设置不改变既有运行的参数。

同一用户的 Host 设置协调器是用户配置的唯一写入者，按登录 SID 选举单实例并持久化版本；各 Engine 转交用户设置的 CAS，订阅已提交的用户版本。协调器不可用时返回具体服务失败，不由多个 Engine 分别覆写用户文件。工作空间配置由该 Engine 的数据库事务写入。Host 用户配置与工作空间配置分开存储和备份；工作空间恢复不能降低用户版本。

| 设置类别 | 作用域 | 默认与范围 | 生效 |
|---|---|---|---|
| 外观与工作台 | 用户 | 系统主题、简体中文、标准密度、遵循系统动态效果；恢复文档与后台询问开启 | immediate |
| 全局热键 | 用户 | Windows/Linux 急停 Ctrl+Alt+Pause，macOS 急停 Ctrl+Alt+F12；录制 Ctrl+Alt+R、暂停/继续 Ctrl+Alt+P | immediate，完整注册成功后切换 |
| 排队上限 | 用户/工作空间 | 16，0..128 | nextRun |
| 物理操作接管 | 用户/工作空间 | pause；可选 ignore | nextRun |
| 图像/模型并发 | 用户/工作空间 | 各 2，1..8 | nextRun |
| 观察会话上限 | 用户/工作空间 | 4，1..16 | nextRun |
| 图像缓存 | 用户/工作空间 | 256MiB，32..4096MiB | immediate |
| 运行附件保留 | 用户/工作空间 | 自动清理默认关闭；确认后采用 30 天、5120MiB；天数 null 表示手动管理 | immediate，只影响后续清理 |
| 观察记录与截图 | 用户/工作空间 | 自动清理默认关闭；确认后采用 30 天、2048MiB；天数 null 表示手动管理 | immediate，只影响后续清理 |
| 预览刷新 | 用户 | 5Hz，1..30Hz | restartAgent |
| 使用统计 | 用户 | 关闭 | immediate |
| 更新 | 用户 | stable 通道，自动检查开启 | immediate，检查不等于安装 |

storage.runRetentionEnabled 与 storage.observationRetentionEnabled 初始均为 false；启用时由本地界面明确确认对应保留范围，不能因读取默认天数或保存其他设置而触发清理。关闭自动清理不删除历史内容，减小容量也不越过已有强引用。

热键语法随设置目录的 hotkeyGrammar 固定：以 `+` 分隔，每个 token 仅去除前后 ASCII 空格/制表；ASCII 大小写不敏感。修饰键为 Ctrl、Alt、Shift、Meta，以及 Windows 兼容键 Win，必须至少包含 Ctrl/Alt/Meta/Win 之一，重复修饰键拒绝；主键恰好一个且必须在最后。规范输出按目录 modifierOrder 排列修饰键，字母主键转为 A..Z，命名主键采用目录拼写，不接受 Cmd、Control、Esc 等别名。

主键允许 A..Z、0..9、F1..F24，以及 Pause、PrintScreen、ScrollLock、Insert、Delete、Home、End、PageUp、PageDown、Left、Right、Up、Down、Space、Tab、Escape、Enter、Backspace。Windows 固定保留组合为 Ctrl+Alt+Delete、Win+L、Win+U、Win+D、Win+Tab、Win+R、Win+E、Alt+Tab、Alt+Escape、Alt+F4、Ctrl+Escape、Ctrl+Shift+Escape；按规范化后的完整组合比较。未知主键或固定保留组合拒绝；macOS/Linux 分别按 reservedByPlatform 检查，其他系统保留及占用由当前后端的原生注册结果裁决。

三个全局功能对合并后的完整有效映射做规范化冲突检查，不能只检查本次修改项。改变组合时先注册全部新键，成功后再注销旧键；不变组合的功能映射原子切换。失败释放本次新注册并保留原配置及原热键。系统支持和占用的原生验收独立于文档语法检查。


## 读取、重置与整批提交

settings.read(scope) 返回 scope、version、baseVersion、完整有效 values、本层显式 overrides、逐键 sources，以及等待 Agent 重启的 pending。当前仅用户键 agent.previewHz 需要重启，因此 pending.savedVersion 为用户设置版本：user 快照以 version 核对，workspace 快照以 baseVersion 核对，不能与工作空间自身版本混用。workspace 的 baseVersion 是其合并所依据的用户版本；user 的 baseVersion 为 null。即使本层未覆盖也返回有效值和来源，界面能区分“当前值”“继承值”和“恢复继承”。

settings.update 使用 scope、expectedVersion、expectedBaseVersion 和 updates 数组。set 写入当前作用域的显式值；reset 删除当前作用域的覆盖，重新继承下一层，不是把 null 当作删除。null 仅在该键值类型允许时有业务含义。一次请求不能重复出现同一键，包括 set 与 reset 的组合；空批次拒绝。

事务先检查完整批次、合并结果、全部跨键条件和权限，再准备必要外部资源。提交时同时比较本层版本与所读用户 baseVersion；任何冲突返回 SETTINGS_CONFLICT 和可重新读取的版本，不提交其中一部分，也不覆盖客户端未保存编辑。用户修改也不能在工作空间批次准备与提交之间无声改变合并结果；协调器为这段短提交提供版本屏障，不在网络或用户确认等待期间持有它。

热键等外部准备全部成功后，以日志化提交意图完成配置版本和资源切换；提交结果丢失先查原请求。崩溃恢复核对配置提交标记：未提交释放新注册，已提交按新配置重建并报告实际可用状态。主题等 UI 状态仅在持久化成功后发布给其他窗口。磁盘写入或外部资源失败不发布部分批次。

结果返回 snapshot、逐键 changes（key、activation、changed）和汇总 activation。相同值的 set 仍可能建立显式覆盖；reset 未存在的覆盖为 changed=false。多个实际生效类别同时存在时 activation=mixed；全部没有变化时 immediate，版本保持不变。immediate 在提交后应用；nextRun 用于新运行或新作业准入，已在途请求不抢断；restartAgent 仅登记 pending，空闲重启成功后清除。下调并发不取消在途工作，调度器等活动数降至新上限后再发新请求。

损坏配置保留原文和最近有效副本，读取返回具体配置损坏错误及恢复入口，不用空配置覆盖。升级遇到新版本未知键须按格式兼容策略保留原始数据并拒绝旧客户端写入，不把未知键当作可自由扩展的设置。

## 默认容量

| 对象 | 默认值 | 超出处理 |
|---|---:|---|
| 每 Engine 活动根运行 / 排队 | 1 / 16 | 排队或明确拒绝 |
| 每运行后台调用 / 深度 | 8 / 8 | 创建调用前拒绝 |
| 图像计算 / 模型请求并发 | 2 / 2 | 有界排队，可取消 |
| 预览刷新 | 5Hz | 合并旧帧 |
| 图像缓存 | 256MiB | 回收可重建项 |
| 客户端事件缓存 | 8MiB / 5,000 条 | 补拉或重取快照 |
| 包解压大小 / 条目数 | 1GiB / 10,000 | 导入前拒绝 |

调整首期预算时，检查内存、存储和输入寿命，并测量实际生效配置下的性能。

## 用户记录与诊断

用户记录显示流程、节点、目标、结果、耗时、具体原因和必要附件。工程日志关联 component、request、run、frame、segment 和异常链，按容量滚动。

默认不记录键盘文本、密钥、完整请求头或所有截图。敏感变量在观察和诊断中遮蔽，实际任务数据不因日志脱敏而改义。导出前显示文件和字段范围。

指标包括输入排队/派发/释放、运行与取消、截图/匹配/模型耗时、事件积压与重连、数据库提交与 WAL、缺失对象、进程树内存/句柄/线程。标签不使用用户文本、窗口标题或无限增长的请求 ID。

## 时间与保留

持久时间统一 UTC，技术消息使用带秒和 Z 后缀的时间戳；查询输入时区先明确转换，区间为左闭右开。运行计时使用单调时钟。

流程、版本和模板默认不按时间删除。运行附件采用用户确认的保留策略，清理排除活动运行、未决效果和备份引用。缓存清理不删除文档。

## 模板、观察与网络配置

| 对象 | 初始配置与生效 |
|---|---|
| 模板提取 | 每作业最多 2,000 候选，暂存默认 30 分钟；选项固定到本次作业 |
| OCR | 按所选语言检查安装状态，失败处理由命名策略决定 |
| 观察会话 | 每 Engine 最多 4 个会话，每会话最多一个在途请求，共用模型并发上限 |
| 观察查询快照 | 默认 5 分钟、不续期；每工作空间 32 个快照、总成员上限 1,000,000；过期重新查询 |
| 观察保留 | 建议记录 30 天、截图 2GiB；用户确认后生效，固定引用除外 |
| 接管策略 | 运行准备的 interruptPolicy 默认 pause，修改作用于新运行 |
| MCP 网络 | 默认不监听；启用时绑定回环地址，最多 32 个会话 |
| 客户端限流 | 每客户端每秒 20 个请求、最多 8 个在途请求，超额明确拒绝 |

图像提取记录候选数、截断数、算法耗时、命名来源、保存阶段和取消耗时。观察记录触发数、忙碌跳过、无变化跳过、模型用量、保存失败及会话终态。网络指标使用匿名客户端类别和有限错误种类，不记录令牌或请求正文。

## 平台默认值

设置目录的 platformDefaults 按当前系统覆盖 default，随后应用用户及工作空间覆盖。支持 platform-settings-v1 的快照携带 platform，用于解释 default 来源；既有未携带平台的 1.0 样例使用 Windows 基线。macOS/Linux 不向缺少该能力的客户端伪造 Windows 默认值。

Meta 在全局快捷键设置中表示当前系统的 Meta 键：macOS Command、Linux Super、Windows Win；Win 拼写仅为 Windows 兼容项，同一组合不能同时包含 Win 和 Meta。Windows 比较冲突与保留组合时将 Meta 统一为 Win。该规则不改写录制轨迹的物理按键。
