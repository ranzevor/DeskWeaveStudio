# 架构决定

这些决定构成 0.1 设计基线。替换方案时应说明受影响的格式、客户端、数据和测试。

## ADR-001：桌面宿主与界面

采用 Tauri 2.12、React 19.3、TypeScript 和 Vite。窗口控制留在 Rust，编辑器和工作台使用 React 组件。画布采用 React Flow，源码采用 Monaco。

这样可以组合图编辑、结构化表单、截图和运行时间线。代价是维护前端、Rust 与 Python 三套工具链，并承担 WebView2、WKWebView 和 WebKitGTK 的分别验证。若关键辅助技术或企业运行环境无法支持，需要先取得对应任务的失败结果，再评估宿主调整；流程与协议不随宿主改变。

## ADR-002：工作空间 Engine 与桌面 Agent 分离

一个 Engine 管理一个工作空间，Rust Agent 管理一个交互桌面。Python 用于流程编排、图像处理和模型适配，便于使用相应库与隔离工作单元；Rust 将系统输入、时钟和释放放在原生控制路径。识别计算和模型等待不占用输入控制线程。

工作空间隔离能约束数据库和运行数据的影响范围；Agent 统一多个 Engine 的输入。相较单一进程，新增了发现、租约、崩溃核对和版本协商成本。合并空闲工作空间服务需先评估实测内存和启动时延，输入所有权仍保持唯一。

## ADR-003：显式入口和有限控制流

流程使用节点数组、显式 entry 和命名出口。普通节点图不允许回边；重复通过 flow.repeat 或同时具备次数与时间上限的 flow.loop 表达，循环体提供受控 break/continue。

该约束使静态校验、图投影和预算可预测。代价是需要把循环体组织成子流程。后续若开放任意回边，需要定义循环作用域、变量可见性、调试和停止行为，并升级流程格式。

## ADR-004：数据表达式

表达式使用 JSON 抽象语法树，只读取 JSON 数据并执行登记的运算。编辑器可提供可读输入界面，再转换为同一 AST。

解释器不接入宿主对象、文件、网络或语言内建函数。相比直接解释脚本文本，格式更长，但跨语言验证和能力限制更明确。

## ADR-005：SQLite 与不可变对象

每工作空间使用 SQLite 保存索引和事务记录，大对象以 SHA-256 内容身份保存。新对象先落盘，再提交引用；备份固定数据库快照及其对象集合。

这种分工适合本地查询、版本历史与便携包。文件和数据库之间没有跨介质原子事务，因此必须处理孤立对象、引用缺失和中断恢复。

## ADR-006：本机通信与公开集成

Windows 内部使用带访问控制的命名管道，macOS/Linux 使用私有运行目录中的 Unix domain socket 与原生对端身份核验；控制、事件和大资源分开传输。MCP 是外部集成适配器，不改变 Engine 和 Agent 的权限检查。

MCP 主协议为 2026-07-28，Bridge 提供 2025-11-25 兼容适配。默认使用 stdio 与显式启用的 Streamable HTTP，旧 HTTP+SSE 独立选择且只走旧版适配。新版的逐请求上下文、发现与订阅适合多客户端接入；兼容适配承担握手、会话及结果转换成本。两代共用一个 Engine 方法目录，授权、分页、请求恢复和输入调度统一执行。旧客户端支持范围改变时，按实际客户端组合调整兼容层并执行 Q28/Q59。

## ADR-007：普通权限与受限提升

Studio 和 Engine 以普通用户身份运行。Windows 需要操作更高完整性目标时，空闲协调后切换为经过用户 UAC 批准的受限 Agent 实例。macOS 使用各项系统隐私授权，Wayland 使用对应系统会话授权；它们不转换为整个应用的管理员/root 身份。

提升实例只有采集和输入协议，不具备任意脚本、程序启动、模块加载和文件写入接口。切换过程中不接受新输入，失败时保留文档与运行记录。

## ADR-008：发布身份

签名安装包、更新包和源码标签分别记录摘要。签名密钥与普通 PR 检查隔离。项目自有源码、文档、契约和原创示例采用 [Apache-2.0](../../LICENSE)，贡献与分发要求见[许可说明](../../LICENSING.md)。

依赖许可按实际材料登记，项目根许可不替代第三方许可。维护职责见[项目维护](../../GOVERNANCE.md)，漏洞报告按[安全报告流程](../../SECURITY.md)提交。

## ADR-009：平台后端与逐屏像素

输入语义、调度、租约和轨迹保真位于共享核心；Windows、macOS、X11、Wayland 采用独立后端。Trajectory 1.1 使用显示身份与屏内像素处理原生坐标差异，保留 1.0 的整数全局物理坐标语义。权限、完整显示覆盖和录制能力分别检测；Portal 捕获不能替代普通桌面的被动录制。代价是维护原生后端、逐平台集成环境与制品链，具体边界见[跨平台架构](platforms.md)。

## ADR-010：受控进程登记与原生连接身份

本机通道采用可信启动控制面的进程登记。登记固定操作系统进程引用、创建标识、安装文件清单与实例 epoch；连接后使用命名管道或 Unix socket 的内核凭据匹配登记，认证内核继续处理一次性票据和业务授权。macOS 动态签名验证与组件清单分别执行，Linux 会话使用 audit 或登录管理器来源。

该分工将进程启动的信任来源与普通消息输入分开，并让 Studio、CLI、Bridge 使用同一认证和业务路径。代价是启动控制面需要管理登记、安装策略和受保护材料交付；通道维护需要协调权限到期、取消与实际 I/O 终态。具体接口与所有权见[原生本机通道](../interfaces/native-transport.md)。

## ADR-011：独立 Engine 进程与启动控制所有权

工作空间启动协调器通过独立服务进程承载共享 Engine。启动解释器和模块来源绑定受信安装清单，启动材料经专用继承管道分块交付；后续管理使用仅面向已登记启动器的原生控制连接，业务客户端使用既有票据与授权内核。工作空间写锁继续由 Engine 进程持有。

控制所有权与业务连接分开：控制方退出停止新准入，已有客户端完成处理后再关闭 Engine。进程登记采用总量预算和共享安装清单，到期索引有界；资源清理失败保留对象直到重试完成。代价是维护启动交换、双向原生身份、受控模块加载和跨平台退出回收，具体接口见[独立 Engine 进程](../development/engine-process.md)。
