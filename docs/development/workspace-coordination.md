# 工作空间发现与启动协调

`deskweave.coordination` 为本地宿主提供工作空间实例发现、并发启动、宿主委托和空闲退出。每个工作空间由一个 Engine 持有写锁；宿主控制连接和业务连接分别登记，共用现有应用服务与原生身份核验。

## 目录与发现

`WorkspaceIdentity` 持有实际目录对象，记录文件系统身份和工作空间身份。空目录绑定实际目录对象，启动计划预分配工作空间身份；Engine 在持有写锁时创建并核对相同身份，失败重试沿用该身份。规范路径用于定位；大小写、符号链接及目录别名按实际对象归并。目录在打开过程中被替换时终止本次操作。

启动锁位于工作空间的 `.engine-start.lock`，与 Engine 的 `.engine.lock` 分别管理启动竞争和数据库写入。锁文件持续保留；锁的占用由操作系统释放。不同工作空间分别竞争自己的启动锁。

发现记录按用户、系统会话及实际目录身份直接定位。记录包含协议版本、工作空间身份、Engine 进程身份、实例 epoch 和端点地址，使用有界编码和原子替换。宿主授权、恢复密钥及业务票据经受保护的继承通道或已认证控制连接交付。

读取记录后核对实际目录、进程创建标识、安装内容及双方认证结果。存活但尚未就绪的实例继续等待；进程已退出的记录在持有启动锁时回收。清理固定原记录的目录与实例身份。

## 可信启动与宿主授权

`StartupAuthority` 由可信本地启动器持有。它明确登记宿主进程、安装策略、权限上限、到期时间及委托能力，生成 `StartupPlan` 和对应的 `HostGrant`。完整启动计划属于工作空间启动管理权限，仅通过受保护的启动通道交付同级管理宿主。受限宿主取得自己的接入授权与非秘密定位信息。计划固定签发权威、授权身份、权限版本及验证材料；双方挑战覆盖这些绑定。

已经接入的受信宿主可通过 `HostSession.register_host` 登记另一个实际进程，并将授权交付该进程。接收端先核对内核报告的对端及已登记进程，再执行宿主授权的双向挑战。挑战绑定目录对象、工作空间、Engine epoch、双方进程身份和随机数。通用解释器与磁盘上的安装文件不作为未知进程自行登记的权限来源。

权限、流程范围、本地编辑属性和委托能力均受签发方上限约束。`manager=True` 增加对其他受控进程的登记和宿主管理操作，业务权限仍受自身策略上限约束。管理宿主可撤销自己及其委托树，其他委托树分别管理。宿主授权与普通业务客户端登记分别识别；接入授权不能改变其他宿主的权限或请求归属。授权到期和撤销在关闭连接前批量使对应宿主及其派生宿主的业务权限与票据失效。宿主进程退出回收其直接能力，其他仍有效的派生宿主继续运行，并保持原始到期时间。

## 启动与共享发布

`WorkspaceCoordinator.open` 首先尝试已登记实例。需要创建实例时取得启动锁，重新发现，再启动缺失实例。目录核对、锁等待、启动交换、认证和就绪共用一次操作预算。

候选完成工作空间打开和原生控制握手后，启动方原子发布候选的定位记录，再提交共享发布请求。定位记录开始对外可见后，启动方取消或断开只释放自身引用；其他已授权宿主可接管就绪流程。共享发布由 Engine 原子确认，重复提交返回同一实例。未发布候选按启动期限回收。

等待方在锁外等待存活候选和关闭中的实例，避免阻塞实例收尾。取消一个等待方不影响启动胜者；候选退出后重新执行发现和竞争。

## 控制连接与资源

每条控制连接独立持有请求序号、登记分块、操作期限和取消状态。登记、授权变更和配额预留由 Engine 串行处理；文件校验与等待受当前预算约束。

控制宿主、业务连接、接入中的已认证进程和未消费的有效宿主授权共同参与活动计数。未消费授权有明确期限；使用后的断开连接可以在授权期限内重新认证。每项进程引用、安装状态、清单元数据和控制连接均受容量约束，关闭失败的资源持续计费并重试释放。协调器关闭时取消在途打开操作，等待其退出并完成资源交接后关闭运行目录。 原子写入失败的临时文件由目录对象继续管理，删除成功后释放占用；后续写入先重试遗留删除。调用 `os.close` 前解除文件描述符数字的本地所有权，关闭错误仍向调用方返回，后续关闭不再次操作该数字。Windows 原生句柄按 `CloseHandle` 的返回结果确认释放。

最后一个活动引用结束后进入空闲宽限。宽限期间的新接入恢复活动状态；关闭提交与新准入使用同一同步边界。进入关闭后停止新准入，等待既有工作结束，再关闭数据库、进程引用和端点。运行实例结束时清理属于自身 epoch 的发现记录。

## 接入与验证

本地窗口、命令客户端及 Bridge 通过同一协调接口取得 `HostSession`，随后按已授予策略建立业务连接。恢复业务请求继续使用既有稳定客户端身份及 `request.status`。

跨平台场景覆盖独立宿主并发首启、目录别名、启动方退出、发布回执丢失、等待取消、失效记录、PID 复用、假端点、错误进程授权、权限收缩、交错登记、容量恢复，以及空闲退出和新接入竞争。

## Python 接口与容量

`StartupAuthority(identity, installation)` 由可信本地启动器创建；`register_host(peer, policy, lifetime=..., manager=...)` 固定实际进程及授权，`seal()` 返回不可变启动计划。完整计划包含 Engine 侧认证密钥，按管理权限交付。宿主密钥为 32 字节，握手使用其 SHA-256 作为 HMAC 密钥；该验证材料同样属于秘密。

`WorkspaceCoordinator(launch, local, directory=None, idle_grace=2.0, max_sessions=64)` 由当前宿主持有。`open(identity, grant, plan=None, create=False, timeout=30, cancel=None)` 返回 `HostSession`；传入启动计划的管理宿主可在实例缺失时启动 Engine。`HostSession.connect()` 为当前宿主取得稳定业务身份并创建连接，保存与恢复继续使用同一业务方法。

| 接口 | 用途 |
|---|---|
| `register_host(peer, policy, lifetime=..., manager=False)` | 登记实际宿主并返回只属于该进程的授权 |
| `authorize`、`issue`、`revise`、`revoke` | 管理当前宿主所属的业务客户端 |
| `revoke_host(grant_id)` | 管理宿主撤销自身或委托树中的授权 |
| `status()` | 读取连接、授权、宿主及容量计数 |
| `diagnostics()` | 管理宿主读取进程诊断尾部 |
| `close()` | 释放当前宿主会话；已打开的业务连接单独关闭 |

默认运行目录按用户与系统会话隔离。Windows 使用 Local AppData 下的私有目录；macOS 使用系统用户临时目录；Linux 依次使用 `XDG_RUNTIME_DIR`、现有 `/run/user/<uid>`，或临时目录下以用户 ID 命名的私有目录。每次访问复核目录对象、所有者和私有权限。

| 对象 | 上限 |
|---|---|
| 宿主登记、同时接入的控制连接 | 各 32 |
| 宿主授权及待提交控制元数据 | 合计 1MiB |
| 发现记录 | 16KiB |
| 单协调器的会话与在途打开 | 默认 64，可设 1～256 |
| 空闲宽限 | 默认 2 秒，可设 0.05～300 秒 |
| 未消费宿主授权的保活 | 最多 30 秒，且不超过授权期限 |
| 安装清单、进程文件状态与业务连接 | 共用[进程容量](engine-process.md#容量与回收) |

目录身份、进程和授权查找使用字典；授权到期使用有界最小堆。登记事务按连接保存，清单存储按安装摘要复用，字节和状态额度统一预留。宿主存活检查只读取原生进程状态，成本与最多 32 个宿主成正比；安装文件在接入与消息核验时按实际字节检查。业务数据继续通过 Engine 的索引分页与内容分块接口访问。

```bash
uv run --frozen python examples/engine/coordination.py
uv run --frozen python tools/test_engine.py tests.engine.test_coordination tests.engine.test_coordination_state -v
```

## 并发读取与发现记录替换

Windows 使用 FileRenameInformationEx 的 REPLACE_IF_EXISTS 与 POSIX_SEMANTICS 原子替换发现记录；已有读取句柄继续指向原文件，新打开操作读取新记录，与 Unix 的替换行为一致。目录身份、相对目录句柄和实例匹配清理继续约束操作对象。标志语义见微软的 [FILE_RENAME_INFORMATION](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/ns-ntifs-_file_rename_information)。
