# 运行计划与持久化基础

## 内部接口

`RunService(workspace, ports=LOGIC_PORTS)` 位于 `deskweave.engine.run_planning`，提供准备与接收接口：

- `prepare(access, params)` 根据固定流程版本构建 `RunPlan`，完成静态校验、依赖读取、输入默认值与类型检查、目标授权和预算计算。
- `accept(access, request_id, params)` 先查询原请求，再为新请求准备计划并原子登记运行，返回既有 run.start 格式的 queued 接收结果。
- `RunStore.create(plan, request_id, authorize=...)` 是应用服务使用的持久化接口，消费内存中的准备结果；`RunStore.read(run_id)` 读取内部完整快照和当前状态。

这些 Python 接口由可信应用服务调用。公共运行方法按[实施路线图](../../ROADMAP.md)接入 Engine 方法注册表。内部完整快照供执行器使用，面向人的变量和运行数据由对应查询服务生成脱敏投影。

`RunAccess` 由认证上下文构造，包含稳定客户端身份、授权引用、授权代次、权限和流程范围。revalidate 检查授权的当前有效性；authorize_target 根据目标槽、目标令牌与类型核对实际目标。创建者、授权引用与代次固定到计划。工作空间请求预算通过 `Workspace.budget` 传入，准备、内容读取、引用核对和最终提交使用同一预算与授权检查。

## 不可变计划

[运行计划格式](../../contracts/run-plan.schema.json)定义内部持久化格式 1.0。RunPlan 保存规范 JSON 字节与规范请求摘要；value() 返回独立解析结果，修改返回对象不会改写计划。

计划固定根流程身份、版本、入口、完整依赖版本及内容摘要、有效输入、初始局部与运行共享变量、敏感输入标记、目标绑定、预算、后台模式和中断策略。流程版本按二元身份索引，资产按版本索引；依赖图访问者对每个流程版本调用一次，完整定义在处理后释放，结果保留不可变引用和内容长度。图中重复使用的子流程只解析一次。

输入只接受已声明参数，缺省使用声明的默认值；缺少必填项或类型不符直接拒绝。原始输入中的 `$expr` 保持普通数据。runVariables 覆盖同名初始共享变量，局部变量取固定定义；敏感参数的默认值同样带敏感标记。指定入口、初始局部变量覆盖和调试配置由后续相应运行入口处理。

省略 limits 时使用默认 10 分钟主动时间、10,000 步、8 层调用、8 个并行调用和 100,000 个输入事件。显式 limits 替换默认请求预算，再逐项与根流程声明上限取较小值。子流程保留自己的固定定义上限供调用时计算。JSON 整值浮点与整数按同一数值处理。

准备过程按实际注册的动作端口检查完整依赖计划，要求 run.execute，并核对所有流程、资产和动作所需权限。声明的必需目标必须提供，目标令牌由授权服务检查；准备过程不发送桌面输入。快照的规范编码最多 32MiB，依赖版本与绑定数量沿用依赖解析器的统一预算。

## 原子接收与重放

接收顺序为：准备计划、校验固定内容、发布不可变对象，然后在一个短事务内核对版本关系与当前授权，写入运行、根调用帧、初始事件、全部依赖强引用及请求回执。事务提交前再次检查授权和请求预算。

根运行初始为 queued，controlVersion/dataVersion 为 0，初始状态事件序号为 1。根调用帧与运行使用复合外键约束，防止跨运行关联；运行对流程和资产的引用保护具体版本。准备失败、对象发布失败、事务失败、截止时间到期或提交前取消，均不留下部分运行。事务前已发布的未引用对象留在对象存储中；其回收须遵循[数据设计](../design/storage.md)的全局强引用与延迟回收规则。

请求身份按客户端隔离。相同 method、规范参数和请求身份返回原接收结果；不同参数返回 REQUEST_CONFLICT。默认中断策略参与规范化，省略与显式 pause 等价。重放检查原授权引用、代次、当前权限和流程范围；授权变化不会借旧请求取得访问权。

## 数据格式与兼容

数据库格式 4 将 command_receipt 的对象归属改为 subject_kind/subject_id，增加授权引用与代次；已有 workflow.save 行保持原请求摘要、结果、时间及 workflow 归属。升级与运行表建立在同一事务完成，失败恢复原结构与版本号。

新增 run、frame、run_event、run_workflow_ref、run_asset_ref，索引覆盖运行拥有者与状态、调用创建次序、事件序号及反向版本引用。格式 1～4 沿既有升级入口升级到当前格式 5，旧版本引擎拒绝写入较新格式。已有流程、资产与保存回执保持原内容。执行位置、变量版本与调用结果的增量扩展见[纯逻辑执行内核](execution-core.md)。

## 验证入口

`uv run --frozen python -m unittest tests.engine.test_runs -q` 覆盖默认值、原始数据、预算、固定版本、依赖去重、目标授权、原子接收、重放、并发、故障回滚与格式升级。三平台 Engine 工作流同时运行源码和安装后的相关契约测试。
